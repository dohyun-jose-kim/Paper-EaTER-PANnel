01 / REVIEW & APPLICATION

Keep selection separate from application

Read the flow without the diagram

Configure and approve processing → retain per-call candidates → compare structure/content → inspect and select under active-review protection. Rerun returns candidates for comparison. Necessary linked changes are provisionally grouped. Assemble the visible content/rename change set. Review exit, final confirmation, and Apply transitions still require approval. Final completion requires processing, review, and Apply completion; override aggregation remains unresolved.

02 / EXPLICIT EXCEPTION

Pending override

Resolve all pending by default. The exception requires user confirmation and disclosure of the selection basis.

How are unselected results chosen?

기본은 모든 pending을 처리하는 것입니다. 사용자가 예외 진행을 확인한 경우에만, 미선택 항목에서 strict majority (> ½)가 있으면 해당 결과를 선택합니다. 없으면 원래 query 순서의 1번 결과를 임의 선택하고 warning을 표시합니다. 이미 선택한 결과는 유지합니다.

Examples: “2 of 3 results agree. This result will be selected.” / “No strict majority. Query 1 will be selected arbitrarily.” These messages do not establish source fidelity. Missing results, query-1 failure, and bypassing mandatory figure review remain open decisions.

03 / ONE-STOP TERMINATION

Closing the interface is not necessarily stopping work

세 선택지는 확정된 요구사항입니다. 기본값, 브라우저 종료 감지, 저장·복구 범위는 아직 정하지 않았습니다.

What must not be assumed?

Force termination does not guarantee preservation of in-flight work. Orderly exit requires a defined recoverable checkpoint. Selection persistence, review-lock restoration, subprocess termination, timeouts, and unexpected shutdown recovery need design. Browser-close interception is not a verified capability.

NEXT / SCENARIO REVIEW FIRST

Decisions this flow should help us make

이 flowchart와 이후 wireframe을 검토한 다음, 결과 허용 기준을 결정합니다.

  1. Review 종료 시 무엇을 고정하고, 어떤 화면에서 최종 승인과 Apply를 허용할 것인가?
  2. 일부 변경만 Apply하는 경우와 pending 후보를 fallback으로 채워 finalize하는 경우를 어떻게 구분할 것인가?
  3. 필수 figure review를 override할 수 있는가? Override 결과를 어떤 review 상태로 표시할 것인가?
  4. Missing calls, query-1 failure, 여러 rerun의 후보를 어떻게 처리할 것인가?
  5. 내용 저장과 rename 중 일부만 성공하면 어떻게 복구하고 표시할 것인가?
  6. 세 종료 방식에서 무엇이 보존되고, 재개 시 문서 보호가 어떻게 복원되는가?
